# 어셈블러 설계와 지원 명세

이 문서는 `RV32IM_어셈블러_과제.pdf`의 요구사항을 현재 코드가 어떻게 처리하는지 설명한다. 페이지 번호는 제공된 25쪽 PDF 기준이다. 실행 명령은 [README](../README.md), 실제 검증 결과는 [RESULTS](RESULTS.md), 작성·검토 과정은 [PROCESS](PROCESS.md)에 정리한다.

## 1. 요구사항과 구현 위치

| PDF | 요구사항 | 현재 구현 |
|---|---|---|
| 1~4쪽 | 단일 `.s` 파일, RV32IM·CSR·기계 모드 명령, raw binary | `main.cpp`가 입력 하나를 받아 전체 처리 단계를 연결한다. ELF나 링커를 사용하지 않는다. |
| 3쪽 | 고정 시작 주소와 기본 심볼 5개 | `layout.cpp`의 `layout_sections()`가 섹션 주소와 기본 심볼을 정한다. |
| 5~10쪽 | 실제 명령어 56개의 인코딩 | `encoder.cpp`의 형식별 함수가 범위를 검사하고 32비트 기계어를 만든다. |
| 11~12쪽 | 가상명령 변환, `li`·`la`의 크기와 상·하위 값 보정 | `assembler.cpp`가 크기를 정하고 `instruction.cpp`가 실제 명령열로 변환한다. `jal`은 아래 교수님 정정을 적용한다. |
| 13쪽 | 라벨·피연산자·주석, 레지스터·숫자·문자 문법 | `parser.cpp`, `operand.cpp`, `value.cpp`가 나누어 처리한다. |
| 14~15쪽 | 섹션 전환, `.equ`, `.globl`/`.global` | `collect_constants()`와 `layout_sections()`가 상수, 섹션, 공개 심볼을 관리한다. |
| 16~17쪽 | 데이터·문자열·예약 공간·정렬 지시어 | `directive_size()`가 크기를 계산하고 `generate_image()`가 바이트를 만든다. |
| 18쪽 | 지원하지 않는 명령·지시어의 처리 | 명령어 표와 지시어 분기에 없는 항목은 오류로 처리한다. 일부 수식과 가상명령은 제공 예제 처리에 필요하여 추가했다. |
| 19~20쪽 | 두 번의 처리 단계, `.bin`·선택 `.lst`, 오류 처리 | 주소 배정 후 바이트를 생성한다. 소스 검증이 끝난 뒤 `output.cpp`에서 파일을 기록한다. |
| 21~24쪽 | 예제 확인과 구현 범위 정리 | 제공된 원본 4개는 `examples/`에 있다. 자동 검증의 범위와 결과는 `RESULTS.md`에 기록한다. |

### `jal`에 대한 교수님 정정

PDF 11쪽의 `jal label → jal a0, label`은 오류이며, 사용자가 전달한 교수님 답변은 다음과 같다.

> PDF의 오류입니다. jal label 은 jal ra, label로 변환되어야 합니다. (11page 중간)

따라서 현재 구현은 `jal label`을 `jal ra, label`로 변환한다. 복귀 주소는 `ra`에 저장되며, `ret`도 `ra`를 사용한다. `jal rd, label`처럼 목적지 레지스터를 명시한 경우에는 지정된 `rd`를 사용한다.

## 2. 처리 흐름과 파일 역할

```text
입력 파일
  → read_source: 줄 정리와 문법 분리
  → collect_constants: .equ 값 계산
  → layout_sections: 섹션 분류, 크기 계산, 주소와 라벨 확정
  → generate_image: 가상명령 변환, 인코딩, 데이터 바이트 생성
  → 선택한 .lst 기록
  → .bin 기록
```

| 파일 | 주요 함수와 역할 |
|---|---|
| [parser.cpp](../parser.cpp) | `parser()`는 문자열·문자 안의 `#`를 보존하며 주석과 앞뒤 공백을 정리한다. `line_parse()`와 `operands_parse()`는 라벨, 명령, 쉼표로 구분된 피연산자를 나눈다. |
| [operand.cpp](../operand.cpp) | `parse_register()`, `parse_integer()`, `parse_integer_char()`, `parse_memory_operand()`가 기본 피연산자를 해석한다. |
| [value.cpp](../value.cpp) | `evaluate_value()`가 상수·심볼·수식을 계산한다. `parse_string_literal()`은 문자열을 실제 바이트로 해석한다. |
| [assembler.cpp](../assembler.cpp) | 원본 줄과 줄 번호를 보존하고, `.equ`를 수집하며, 명령어·지시어의 크기를 계산한다. |
| [encoder.cpp](../encoder.cpp) | 명령어 표를 조회하고 각 형식의 비트 위치에 레지스터와 즉시값을 배치한다. |
| [instruction.cpp](../instruction.cpp) | `assemble_instruction()`이 가상명령을 변환하고 적절한 인코더를 호출한다. |
| [layout.cpp](../layout.cpp) | `layout_sections()`가 주소를 정하고 `generate_image()`가 text와 data의 출력 이미지를 만든다. |
| [output.cpp](../output.cpp) | 입력·출력 경로의 충돌을 확인하고 바이너리와 listing을 기록한다. |
| [main.cpp](../main.cpp) | 명령행 인수, 단계별 실패 확인, 결과 출력과 종료 상태를 처리한다. |

각 단계는 결과 구조체의 `is_success`와 `err`로 실패를 전달한다. 소스 줄에 연결된 오류에는 `line N:`을 붙인다. 파일 열기 실패나 명령행 오류처럼 특정 소스 줄과 관계없는 오류는 별도로 출력한다.

## 3. 주요 자료구조

| 자료구조 | 저장하는 내용 |
|---|---|
| `source_line` | 원본 줄 번호, 원본 문자열, 라벨, 명령어 또는 지시어 이름, 피연산자 벡터 |
| `source_file` | 해석된 `source_line` 목록과 오류·성공 상태 |
| `constants_rtn` | `.equ` 이름을 signed 64비트 값에 연결한 `unordered_map` |
| `inst_size_rtn` | 해당 줄이 차지할 바이트 수와 오류·성공 상태 |
| `value_rtn` | 계산 결과, 오류·성공 상태, 미정의 심볼 때문에 계산하지 못했는지 여부, 심볼 포함 여부 |
| `placed_line` | 원본 줄, 섹션 `T/D/B`, 확정 주소, 예약한 크기, 생성한 바이트 |
| `layout_rtn` | 배치된 줄 목록, 공유 심볼 표, 심볼의 영역 표, 공개 심볼 집합, 섹션 경계 주소 |
| `instruction_rtn` | 한 소스 명령에서 만들어진 32비트 기계어 벡터 |
| `image_rtn` | 최종 `.bin`에 기록할 바이트 벡터 |

라벨 표는 섹션마다 따로 만들지 않고 하나로 공유한다. 따라서 `.text`와 `.data`에서 같은 라벨을 사용해도 중복으로 검출된다. 심볼 영역 표의 `T`, `D`, `B`는 주소 심볼을, `=`는 `.equ` 상수를 구분하는 데 사용한다.

## 4. 소스 해석과 상수

소스 한 줄은 `[라벨:] [명령 또는 지시어와 피연산자] [# 주석]` 형태다. 빈 줄과 주석만 있는 줄은 저장하지 않지만, 라벨만 있는 줄은 주소 배정을 위해 보존한다. CRLF 입력의 마지막 `\r`는 해석 전에 제거하고 원래 줄 번호는 유지한다.

라벨과 상수 이름에는 영문자, 숫자, `_`, `.`을 사용할 수 있으며 첫 문자는 숫자가 될 수 없다. 이름은 대소문자를 구분한다. 빈 라벨, 잘못된 이름, 중복 이름, 기본 심볼의 재정의는 오류다.

레지스터는 `x0`~`x31`과 ABI 이름을 지원하며 `fp`는 `s0`와 같은 `x8`이다. 메모리 피연산자는 `offset(rs1)` 형태이고, `(sp)`처럼 offset을 생략하면 0이다. `(COUNT-4)(sp)`처럼 offset 부분에 수식을 사용할 수도 있다.

`.equ NAME, expression`은 소스 전체에서 먼저 수집한다. 아직 계산하지 못한 상수는 다음 반복에서 다시 계산하므로 다른 `.equ`의 전방 참조가 가능하다. 한 번의 반복에서도 해결된 이름이 없으면 미정의 또는 순환 정의로 실패한다. 이 단계에서 사용할 수 있는 기본 주소 상수는 `TEXT_START`와 `_stack_top`이며, 배치가 필요한 라벨이나 `_data_start` 등에 의존하는 `.equ`는 지원하지 않는다.

### 수식 처리

PDF 13쪽은 수식을 생략할 수 있다고 설명하지만, 제공 예제를 수정 없이 처리하기 위해 아래 연산을 추가했다. `value.cpp`는 작은 상태 구조체와 일반 함수로 토큰과 우선순위를 처리한다.

| 높은 순서부터 | 지원하는 연산 |
|---|---|
| 괄호·단항 | `(…)`, `+`, `-`, `~` |
| 곱셈 계열 | `*`, `/`, `%` |
| 덧셈 계열 | `+`, `-` |
| 시프트 | `<<`, `>>` |
| 비트 연산 | `&`, 그다음 `^`, 그다음 `\|` |

같은 우선순위의 이항 연산은 왼쪽부터 계산한다. 10진수, `0x`/`0X` 16진수, `0b`/`0B` 2진수, 문자 상수와 심볼을 값으로 사용할 수 있다. 계산은 signed 64비트 범위에서 하며 오버플로, 0으로 나누기, 0~63 범위 밖의 시프트를 거부한다. 음수의 오른쪽 시프트는 부호를 유지하는 결과로 계산한다.

실제 예제에서 사용하는 식에는 `(1 << IRQ_TIMER) | (1 << IRQ_KEY)`, `0x80000000 | IRQ_TIMER`, `SCREEN_H * 512 / 4`, `-'0'`, `-'a' + 10`이 있다.

## 5. 섹션 배치와 주소 계산

`layout_sections()`는 기본 섹션을 `.text`로 두고 소스 줄을 `.text`, `.data`, `.bss`의 세 벡터에 분류한다. 같은 섹션이 다시 나오면 기존 내용 뒤에 이어 붙인다. 섹션 전환 지시어 앞에 붙은 라벨은 전환 전 섹션의 현재 위치에 남긴다.

분류 후에는 text, data, bss 순서로 주소를 계산한다. 섹션을 바꿔가며 작성한 소스에서도 최종 이미지는 이 순서를 따른다.

| 기본 심볼 | 값 |
|---|---|
| `TEXT_START` | `0x00010000` |
| `_data_start` | text 끝을 16바이트 경계로 올린 주소 |
| `_bss_start` | data 끝을 16바이트 경계로 올린 주소 |
| `_bss_end` | BSS 예약 공간의 끝 주소 |
| `_stack_top` | `0x00040000` |

예를 들어 text 크기가 20바이트, data 크기가 6바이트, BSS 크기가 12바이트라면 다음처럼 배치된다. 이는 계산을 설명하기 위한 예시다.

```text
text: 0x10000 ~ 0x10013     20바이트
정렬: 0x10014 ~ 0x1001F     12바이트
data: 0x10020 ~ 0x10025      6바이트
bss 시작: 0x10030
bss 끝:   0x1003C
bin 크기: 0x10026 - 0x10000 = 38바이트
```

`.align k`는 섹션 내부에서 0부터 센 위치가 아니라 현재의 실제 주소를 기준으로 계산한다. 정렬 단위를 `alignment = 2^k`라고 하면 추가 크기는 다음과 같다.

```text
remainder = current_address % alignment
padding = remainder가 0이면 0, 아니면 alignment - remainder
```

명령어는 `.text`에서만 허용하고 주소가 4의 배수인지 검사한다. `.bss`는 `.space`, `.align`, 라벨 및 `.equ`·`.globl` 같은 메타데이터만 허용한다. BSS의 시작과 끝을 계산하지만, 이 어셈블러가 실행 중 메모리를 0으로 초기화하는 코드를 자동 생성하지는 않는다.

## 6. 명령어 크기와 가상명령

일반 명령어는 모두 4바이트다. `la`는 항상 8바이트이며, `li`는 값에 따라 4바이트 또는 8바이트다. 배치할 때 아직 미정인 심볼 때문에 `li`의 값을 구하지 못하면 8바이트를 예약한다. 나중에 값이 작다는 것이 밝혀져도 두 명령을 생성하여 이미 정한 라벨 주소가 바뀌지 않게 한다.

`li`는 `-2147483648`~`4294967295` 범위의 값을 받고, `2147483647`보다 큰 값은 `2^32`를 빼서 RV32의 부호 있는 값으로 해석한다. 예를 들어 `0xFFFFFFFF`는 -1이므로 배치 시 값을 알면 `addi` 하나가 된다. 이 정규화는 `li`의 규칙이며 일반 I형 즉시값의 허용 범위를 넓히는 규칙은 아니다.

두 명령이 필요한 경우에는 하위 12비트를 signed 12비트 값 `lo`로 해석하고 `hi = (value - lo) / 4096`으로 구한다. 이렇게 하면 PDF 12쪽의 상위 값 보정 규칙을 만족하면서 음수에 대한 C++ 시프트에 의존하지 않는다. `lo`가 0이어도 두 번째 `addi`를 생략하지 않는다.

`la`는 목적지 주소와 첫 번째 `auipc` 주소의 차이를 RV32의 32비트 값으로 해석한 뒤 같은 방법으로 `hi`와 `lo`를 계산한다. 두 번째 `addi`의 주소를 기준으로 다시 계산하지 않는다.

| 가상명령 | 변환 결과 |
|---|---|
| `li rd, value` | 작은 값은 `addi rd, x0, value`, 그 외에는 `lui rd, hi`와 `addi rd, rd, lo` |
| `la rd, target` | `auipc rd, hi`와 `addi rd, rd, lo` |
| `mv rd, rs` | `addi rd, rs, 0` |
| `nop` | `addi x0, x0, 0` |
| `not rd, rs` | `xori rd, rs, -1` |
| `neg rd, rs` | `sub rd, x0, rs` |
| `j target` | `jal x0, target` |
| `jr rs` | `jalr x0, 0(rs)` |
| `jal target`, `call target` | `jal ra, target` |
| `ret` | `jalr x0, 0(ra)` |
| `beqz rs, target`, `bnez rs, target` | 각각 `beq`, `bne`에서 두 번째 비교 레지스터를 `x0`으로 지정 |
| `bgt a, b, target`, `bgtu a, b, target` | 각각 `blt b, a, target`, `bltu b, a, target` |
| `ble a, b, target`, `bleu a, b, target` | 각각 `bge b, a, target`, `bgeu b, a, target` |
| `csrr rd, csr` | `csrrs rd, csr, x0` |
| `csrw csr, rs` | `csrrw x0, csr, rs` |
| `csrsi csr, imm`, `csrci csr, imm` | 각각 `csrrsi x0, csr, imm`, `csrrci x0, csr, imm` |
| `csrs csr, rs` | 예제에서 추가 사용: `csrrs x0, csr, rs` |
| `bltz rs, target` | 예제에서 추가 사용: `blt rs, x0, target` |
| `bgtz rs, target` | 예제에서 추가 사용: `blt x0, rs, target` |

`call`은 과제 조건대로 `jal` 한 명령의 거리 안에서만 지원한다. 먼 호출을 위한 별도 명령열로 자동 확장하지 않는다.

## 7. 실제 명령어 인코딩

`instruction_format()`이 기존 명령어 표에서 형식을 찾고, `assemble_instruction()`이 피연산자 개수를 확인한 뒤 아래 인코더를 호출한다. 레지스터·즉시값 필드는 마스크와 시프트로 32비트 코드에 배치한다.

| 형식 | 개수 | 처리와 핵심 검사 |
|---|---:|---|
| R | 18 | 정수 연산 10개와 M 확장 8개. `rd`, `rs1`, `rs2`, `funct3`, `funct7` 배치 |
| I | 15 | 즉시 연산, load, `jalr`. 일반 즉시값은 -2048~2047, 시프트 양은 0~31 |
| S | 3 | store의 12비트 즉시값을 상위 7비트와 하위 5비트로 분리 |
| B | 6 | 오프셋 -4096~4094 및 짝수 검사. 비트 12, 10~5, 4~1, 11을 지정 위치에 배치 |
| U | 2 | `lui`, `auipc`. 20비트 값은 -524288~1048575를 받아 하위 20비트 배치 |
| J | 1 | `jal`. 오프셋 -1048576~1048574 및 짝수 검사 |
| CSR | 6 | CSR 번호 0~4095, 레지스터 원본 또는 즉시 원본 0~31 |
| 고정 코드 | 5 | `ecall`, `ebreak`, `fence`, `mret`, `wfi` |

고정 코드는 각각 `0x00000073`, `0x00100073`, `0x0FF0000F`, `0x30200073`, `0x10500073`이다. `fence`는 PDF 9쪽대로 인자 없는 형태만 받는다.

분기·점프의 목적지 처리에는 다음 규칙을 사용한다.

- 숫자나 `.equ` 상수만으로 된 식은 현재 PC에 더할 오프셋으로 사용한다. PDF 8쪽의 `beq a0, a1, +8`이 이 경우다.
- 식에 라벨 또는 기본 주소 심볼이 하나라도 들어 있으면 식 전체를 목적지 주소로 보고 현재 명령어의 PC를 뺀다.
- `.equ`와 주소 심볼의 구분은 `symbol_sections`를 사용한다. 일반 GNU 어셈블러의 재배치 수식 전체를 구현한 방식은 아니다.

CSR 이름 표는 다음과 같다. 이름 대신 계산 가능한 숫자식을 사용할 수도 있다.

| 이름 | 번호 | 이름 | 번호 | 이름 | 번호 |
|---|---:|---|---:|---|---:|
| `mstatus` | `0x300` | `mie` | `0x304` | `mtvec` | `0x305` |
| `mscratch` | `0x340` | `mepc` | `0x341` | `mcause` | `0x342` |
| `mtval` | `0x343` | `mip` | `0x344` | `mhartid` | `0xF14` |

## 8. 데이터 지시어와 출력 이미지

| 지시어 | 크기와 값 처리 |
|---|---|
| `.byte` | 항목마다 1바이트, 값 -128~255, 피연산자 1개 이상 |
| `.half` | 항목마다 2바이트, 값 -32768~65535, 피연산자 1개 이상. 홀수 주소는 오류 |
| `.word` | 항목마다 4바이트, 값 -2147483648~4294967295. 라벨 주소와 `.equ`도 해석. 자동 정렬은 하지 않음 |
| `.ascii` | 큰따옴표 문자열 하나를 해석한 바이트 수 |
| `.asciz` | 같은 문자열 바이트 뒤에 0 한 바이트 추가 |
| `.space n` | n바이트 예약. text와 data에서는 0으로 채우고 BSS에서는 크기만 계산 |
| `.align k` | 실제 주소 기준으로 필요한 정렬 공간을 0으로 채움. BSS에서는 크기만 계산 |
| `.equ`, `.globl`, `.global` | 자체 바이트를 생성하지 않음 |

문자열의 길이는 소스 표기상의 글자 수가 아니라 실제 저장하는 바이트 수다. `\n`, `\r`, `\t`, `\b`, `\f`, `\0`, `\\`, `\'`, `\"`를 지원한다. 예를 들어 `.ascii "A\n"`는 2바이트, `.asciz "A\n"`는 3바이트다. 알려지지 않은 이스케이프, 본문의 이스케이프되지 않은 큰따옴표, 문자열 대신 숫자를 준 입력은 오류다.

`generate_image()`는 `data_end - TEXT_START` 크기의 0으로 채운 벡터를 만든다. 각 줄의 바이트는 `줄 주소 - TEXT_START` 위치에 기록한다. 기계어와 2·4바이트 데이터는 낮은 바이트부터 기록한다. 예를 들어 `0x12345678`은 `78 56 34 12`로 저장된다.

각 줄이 실제로 만든 바이트 수가 배치 단계에서 예약한 크기와 일치하는지 검사한다. `.space`와 `.align`에 해당하는 출력 공간은 처음 생성한 0을 그대로 사용한다. `.bss`의 바이트와 data 뒤에서 BSS 시작까지의 정렬 공간은 파일에 넣지 않는다. data가 비어 있어도 data 시작 주소는 16바이트 정렬 규칙으로 정하며, 파일은 그 data 끝 주소까지다.

선택 출력인 `.lst`에는 원본 줄 번호와 소스, 주소, 확장된 기계어 또는 데이터 바이트를 기록한다. 0으로 채우는 줄과 BSS 예약 줄에는 예약 크기를 표시한다. 마지막에는 심볼 값, 영역, 공개 심볼의 `G` 표시와 이름을 기록한다.

## 9. 오류 처리와 현재 제약

소스 분석·상수 수집·배치·바이트 생성 중 오류가 나면 이후 단계를 실행하지 않고 종료한다. 따라서 소스 오류가 있는 실행은 새 `.bin`을 만들거나 기존 `.bin`을 덮어쓰지 않는다. 입력 경로와 출력 경로가 같거나 `.bin`과 `.lst` 경로가 같으면 거부한다.

출력은 일반 파일 스트림으로 기록한다. 쓰기 중 디스크나 I/O 오류가 발생하면 오류를 보고하지만, 이미 기록 중인 파일을 이전 상태로 되돌리는 기능은 없다. `.lst`를 요청한 경우에는 listing을 먼저 기록하므로 그 뒤 바이너리 기록만 실패하면 listing은 남을 수 있다.

| 항목 | 현재 제약 |
|---|---|
| 주소 | 섹션 주소와 끝 주소가 `uint32_t` 범위를 넘으면 오류 |
| 한 줄의 크기 | `int byte_size`에 맞춰 `INT_MAX` 이하만 허용 |
| `.align k` | 64비트 정수로 계산하기 위해 0~63만 허용하고, 계산한 추가 크기도 `INT_MAX` 이하인지 검사 |
| 수식 | signed 64비트 범위. 괄호·단항 연산의 과도한 중첩은 128단계 검사로 제한 |
| 배치에 필요한 값 | `.space`·`.align`은 그 시점에 이미 계산 가능한 값이 필요 |
| `.equ` | 상수 간 전방 참조는 지원하지만 배치 후에야 알 수 있는 라벨 주소에 의존하는 정의는 지원하지 않음 |
| 문자열 | `.ascii`·`.asciz`는 한 번에 문자열 하나. 문자열의 비이스케이프 부분은 입력의 바이트 그대로 저장 |
| 출력 크기 | 전체 이미지를 메모리 벡터로 만들므로 실제 메모리 용량의 영향을 받음. 할당 실패는 오류로 보고 |
| 범위 밖 기능 | ELF, 링킹, 재배치, `%hi`·`%lo`, 매크로, 지역 숫자 라벨, `.section`, 실수·압축·원자 명령 등은 지원하지 않음 |

이 명세는 구현된 어셈블 동작을 설명한다. 제출자는 이후 CPUlator에서 제공 예제 1~4의 동작을 직접 확인하고 약 9분의 시연 영상 촬영을 완료했다. 자동 검사와 CPUlator 실행 결과, 실행·촬영 완료 보고일은 [RESULTS.md](RESULTS.md)에 구분해 기록했다.
