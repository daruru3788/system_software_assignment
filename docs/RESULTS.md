# 검증 결과

## 검증 목표와 결과 요약

검증은 명령어의 비트 배치, 프로그램 전체의 주소·바이트 일관성, 잘못된 입력의 차단이라는 세 관점으로 구성했다. 대표 기계어의 기대값과 가상명령에 대응하는 실제 명령열을 비교하고, 섹션 배치와 오류 조건을 별도 입력으로 확인했다. 제공 예제는 원본을 수정하지 않고 통합 입력으로 사용했다.

최종 C++17 빌드, 자동 검사 16개 테스트 메서드, 별도의 수식 경계 검사 2,567개가 통과했다. 제공 예제 4개의 바이너리와 listing을 생성했으며, 결과 파일의 크기와 SHA-256을 아래에 기록했다. 이후 제출자가 CPUlator에서 네 예제의 동작을 직접 확인하고 약 9분의 시연 영상 촬영을 완료했다.

| 검증 수준 | 방법 | 확인하는 내용 |
|---|---|---|
| 명령어 인코딩 | 56종 대표 입력의 예상 비트 패턴과 비교 | opcode·레지스터·즉시값 필드와 바이트 순서 |
| 변환과 배치 | 가상명령/실제 명령열 비교, 주소·데이터 바이트 검사 | `li`·`la`, 전방 참조, 섹션 정렬과 BSS 제외 |
| 오류 처리 | 잘못된 입력, 기존 결과 파일, 입력·출력 경로 충돌 | 실패 진단과 소스 오류 시 출력 보존 |
| 예제 통합 | 제공 원본 4개의 어셈블과 listing 생성 | 예제에서 사용하는 명령·지시어·수식의 처리 |
| CPUlator 실행 | 제출자가 제공 예제 1~4를 로드하여 실행하고 영상 촬영 | 생성한 바이너리의 시뮬레이터 실행 동작 |

자동 검사 결과는 보존한 실행 로그에, CPUlator 실행과 촬영 결과는 제출자의 완료 보고에 근거한다. 두 검증의 범위와 기록 시점을 아래에 구분했다.

## CPUlator 실행 및 시연 영상

실행·촬영 완료 보고일: 2026-11-29. 제출자가 직접 만든 어셈블러로 생성한 바이너리를 CPUlator의 `rv32-de10-lite` 환경에 로드하여 제공 예제 1~4의 동작을 확인했다. 과제에서 지정한 바이너리 로드 주소와 시작 PC는 `0x00010000`이다.

| 예제 파일 | 예제 내용 | 실행 결과 |
|---|---|---|
| `asm_example1.s` | 스톱워치 | CPUlator 동작 확인, 영상 촬영 완료 |
| `asm_example2.s` | 반응 속도 측정기 | CPUlator 동작 확인, 영상 촬영 완료 |
| `asm_example3.s` | VGA 공 튀기기 | CPUlator 동작 확인, 영상 촬영 완료 |
| `asm_example4.s` | JTAG UART 명령 해석기 | CPUlator 동작 확인, 영상 촬영 완료 |

시연 영상은 약 9분이며 제공 예제 네 개의 실행을 담았다. 제출 폼에서 요구하는 최소 두 개 이상의 예제 시연을 충족하는 구성이다. 영상 링크는 제출 폼의 동영상 링크 항목에 기재한다. 이 실행 결과는 CPUlator에서 확인한 결과이며 실제 보드 실행 결과는 포함하지 않는다.

## 실행 환경과 통과 항목

빌드·자동 검사일: 2026-11-28. Windows의 GCC C++17과 Python 표준 라이브러리를 사용했다.

환경은 MSYS2 GCC `15.2.0`(Rev8), Python `3.13.5`다. 실제 실행 출력 발췌는 [verification-2026-11-28.txt](logs/verification-2026-11-28.txt)에 보존했다. 저장소의 자동 검사는 `tests/test_assembler.py`로 재현할 수 있고, 별도로 수행한 임시 수식 검사의 통과 수는 같은 로그에 구분해 기록했다.

| 검사 | 확인 결과 |
|---|---|
| 전체 소스 컴파일·링크 | 통과 |
| Windows 기본 빌드 `build.cmd` | 통과, `assembler.exe` 생성 |
| 정수 축소 변환·반환 누락을 오류로 취급한 빌드 | 통과 |
| `tests/test_assembler.py` | 16개 테스트 메서드 모두 통과 |
| 실제 명령어 인코딩 | 56개 명령어의 대표 입력에 대한 기계어 확인 |
| 가상명령 | 대응하는 실제 명령열과 바이트 비교 통과 |
| 수식 계산 별도 검사 | signed 64비트 연산 경계·우선순위 2,567개 확인 통과 |
| 원본 `asm_example1.s` | 수정 없이 성공, `example1.bin` 716바이트 |
| 원본 `asm_example2.s` | 수정 없이 성공, `example2.bin` 796바이트 |
| 원본 `asm_example3.s` | 수정 없이 성공, `example3.bin` 884바이트 |
| 원본 `asm_example4.s` | 수정 없이 성공, `example4.bin` 2,380바이트 |

16개 테스트 메서드 내부에는 여러 입력을 순회하는 하위 검사가 포함된다. 알려진 기계어 값, 56개 실제 명령어, 가상명령 대응, `li` 경계, `la`의 기준 PC, 섹션 재등장, 16바이트보다 큰 정렬, BSS 파일 제외, 문자열 이스케이프, 상수 수식, 잘못된 입력과 기존 출력 보존을 확인했다.

최종 실행으로 `project` 폴더에 `assembler.exe`와 `example1`~`example4`의 `.bin`·`.lst` 파일을 생성했다. 이 빌드 산출물들은 `.gitignore`로 제외하며, 원본 소스와 실행 명령으로 다시 만들 수 있다.

## 원본과 출력 파일 확인

`examples/`의 네 `.s` 파일을 제공 ZIP의 동일한 이름 항목과 바이트 단위로 비교했으며 모두 일치했다. 원본 예제에 명령어·상수·문자열 수정을 가하지 않았다.

| 생성 파일 | 크기 | SHA-256 |
|---|---:|---|
| `example1.bin` | 716 | `5c9f9c669211ed4f4d044d3d36e1e85981c4f537fe287070afb8ab15af8c7f93` |
| `example2.bin` | 796 | `bf4dc2a0d47b7603cef7470c256bb575e19462b7aa5983a1ec5b282fc7322f0d` |
| `example3.bin` | 884 | `94f14182674b7642e173f44c4f7414a0214d8200211168b0514757ae1e79db7d` |
| `example4.bin` | 2,380 | `4ae0d8482467f67391d0f2e6ea3c61480a2b6d4eb0571c9b88f69ced6be00584` |

PowerShell의 `Get-FileHash example1.bin -Algorithm SHA256`으로 재생성한 파일을 비교할 수 있다. SHA-256은 이 실행에서 생성한 바이트와의 일치 여부를 확인하는 수단이며 CPUlator에서의 실행 성공을 뜻하지 않는다.

## 검사 입력과 확인 내용

| 검사 영역 | 대표 입력 또는 조건 | 확인한 결과 |
|---|---|---|
| 실제 명령어 | `sw t0, 8(sp)`, `beq a0, a1, +8` | 각각 `00512423`, `00B50463` 및 리틀 엔디언 바이트 |
| 전체 인코딩 | R/I/S/B/U/J/CSR/fixed의 56개 | 각 비트 필드와 opcode 비교 |
| 가상명령 | `jal label`, `call`, `ret`, CSR·조건 분기 별칭 | 대응하는 실제 명령열과 바이너리 일치 |
| `li` | -2048, 2047, 2048, -2049, `0xffffffff`, `0x80000000` | 4/8바이트 크기, 부호·상위/하위 보정 |
| `la` | 앞에 `nop`이 있고 뒤 data에 대상이 있는 경우 | 첫 `auipc` PC를 기준으로 계산 |
| 전방 참조 | `li t0, end - TEXT_START` | 예약한 8바이트 크기 유지 |
| 섹션 | text/data 재등장, `.align 5`, 섹션 전환 줄의 라벨 | 실제 주소 기준 배치와 라벨 보존 |
| 데이터 | 음수 `.byte/.half/.word`, 주소 상수, 문자열·이스케이프 | 범위·바이트 순서·문자열 끝의 0 |
| BSS | `.space`, `.align`, 기본 심볼 | 메모리 크기는 계산하고 파일에는 제외 |
| 수식 | 시프트·비트 OR·곱셈/나눗셈·음수 문자·상수 전방 참조 | 제공 예제에 필요한 계산 |
| 오류 | 미정의/중복/빈 라벨, 범위 밖 값, 피연산자·문자열 오류 | 비정상 종료, 진단, 새 `.bin` 없음 |
| 기존 파일 | 잘못된 소스와 이미 존재하는 `.bin` | 이전 파일 내용 유지 |
| 출력 경로 | 입력 파일을 출력 파일로 지정 | 입력 파일 보존, 오류 반환 |

초기 listing 검사는 global 표시가 이름 뒤에 나오는 열 순서를 가정했다. 실제 요구사항은 이름·값·섹션·global 표시이므로 검토자가 열 순서에 의존하지 않도록 검사를 고쳤다. 빈 라벨과 과도한 출력 처리 구조에 대한 수정은 [PROCESS.md](PROCESS.md)에 기록했다.

## 결과 재현

저장소 루트에서 다음 명령을 실행한다.

```powershell
.\build.cmd
python tests\test_assembler.py .\assembler.exe
.\assembler.exe examples\asm_example1.s -o example1.bin --list example1.lst
```

네 예제의 결과를 모두 다시 만들려면 다음을 실행한다.

```powershell
foreach ($example in 1..4) {
    .\assembler.exe "examples/asm_example$example.s" -o "example$example.bin" --list "example$example.lst"
    if ($LASTEXITCODE -ne 0) { throw "Example $example failed" }
}
```
